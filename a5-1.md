**Assumptions:** "8 to 20 characters" includes both ends. A rejected password shows a validation error.

| ID | Test idea | Test input | Expected result |
|----|-----------|------------|-----------------|
| TI-01 | Shortest valid length (8 chars) with a digit and an uppercase letter | `Abcdefg1` | Accepted |
| TI-02 | One character below the minimum (7 chars) | `Abcdef1` | Rejected (too short) |
| TI-03 | Longest valid length (20 chars) with a digit and an uppercase letter | `Abcdefghijklmnopqr12` | Accepted |
| TI-04 | One character above the maximum (21 chars) | `Abcdefghijklmnopqrs12` | Rejected (too long) |
| TI-05 | Valid length and an uppercase letter, but no digit | `Abcdefghij` | Rejected (no digit) |
| TI-06 | Valid length and a digit, but no uppercase letter | `abcdefgh12` | Rejected (no uppercase letter) |

**Other ideas I'd add:** an empty password, a password with only digits and uppercase letters (such as `ABCDEFG1`), and checks for special characters, spaces and non-ASCII uppercase letters such as `É`. The requirement doesn't say how those last three should behave, so it's worth asking.
